CODE REVIEW DOCUMENT
====================
Remote Monitor & Control System v6.0.0

========================================
FILE 1: agent/main.go (Go - 6.7MB .exe)
========================================

PURPOSE: Windows agent executable. Captures all displays, sends to server,
receives control commands, supports tunnel expose, file transfer, push updates.

KEY STRUCTURES:

Message struct - JSON message format for WebSocket communication
  Type: string - message type
  AgentId: string - unique identifier for this agent
  Name: string - computer hostname
  Frame: string - base64-encoded JPEG screenshot
  Fps: int - frames per second setting
  Display: int - display index (0 = primary, 1+ = secondary)
  Command: string - command or filename
  Params: map[string]string - control parameters (x, y, key)

KEY FUNCTIONS:

main() - Entry point
  - Checks for --server flag to run in server mode
  - Prevents duplicate instances (lock file)
  - Tries to start local server (port 3000)
  - Also connects to cloud/server as agent
  - Infinite reconnect loop (3 second delay)

runServer() - Local server mode (agent acts as server/relay)
  - HTTP server on port 3000
  - WebSocket relay for agents
  - Serves embedded dashboard HTML (grid tile layout, light theme)
  - Tracks all connected agents with IPs
  - Forwards frames (with display index) to viewers
  - Forwards control, become-server, file-transfer, request-file messages
  - Starts embedded agent for this PC too

connect() - Connect to cloud server as agent
  - Reads urls.ini for custom server URLs
  - Tries each URL in order until one connects
  - Sends agent-hello registration
  - Runs goroutine to receive messages
  - Sends frames for ALL displays in loop (at configured FPS)
  - Handles: set-fps, control, push-update, switch-server,
    file-transfer, request-file, become-server, start-tunnel, cleanup-logs

captureDisplay(n) - Screen capture for specific display
  - Uses github.com/kbinani/screenshot
  - Captures display n by index
  - Encodes as JPEG quality 50
  - Returns base64 string

captureFrames() - Capture all displays
  - Iterates all displays via numDisplays()
  - Returns slice of Message{Frame, Display} for each display
  - Used in both cloud and local frame loops

Multi-Display Support:
  - numDisplays() - queries total display count
  - captureDisplay(n) - captures specific display
  - captureFrames() - captures all displays at once
  - Message.Display field tracks which display a frame belongs to
  - Both frame loops (cloud and embedded) use captureFrames()
  - Server and dashboard forward Display field to viewers

Tunnel/Expose:
  - startTunnel() - starts bore tunnel for remote access
  - become-server handler - saves server preference + starts tunnel
  - Tunnel status reported back to dashboard via WebSocket

File Transfer:
  - handleFileTransfer() - saves received files to C:\ProgramData\SystemHelper\received\
  - receivedDir() returns "C:\\ProgramData\\SystemHelper\\received"
  - handleFileRequest() - reads a file from agent and sends back via WebSocket
  - Old received folder cleaned on startup

Push Updates:
  - handleRemoteUpdate() - receives base64 .exe, saves to temp, replaces running .exe
  - Restarts with new version via os.Executable() replacement
  - Called with correct (filename, data) parameter order

hideCmd() - Hide windows popups
  - Defined in exec_windows.go (HideWindow: true, build tag: windows)
  - Defined in exec_other.go (no-op, non-windows builds)
  - Called on ALL 6 exec.Command() operations:
    1. handleRemoteUpdate (new .exe start)
    2. preventDuplicate (taskkill old process)
    3. cleanTempFiles (cmd cleanup commands)
    4. startTunnel (SSH tunnel)
    5. PowerShell download (bore tunnel setup)
    6. bore tunnel executable

Dashboard Features (embedded):
  - Light theme (#f0f2f5 background, #2563eb accent, white cards)
  - Grid layout with tiles (flex-wrap, 320px min, no sidebar)
  - Each tile: hostname, IP, screen thumbnails (per display), Open/Expose buttons
  - Multi-display thumbnails with click-to-expand full-screen modal
  - Open button → http://agent-ip:3000 in new tab
  - Expose button → become-server message (start tunnel)
  - File transfer: Send files to agent, request files from agent
  - Push Update: select .exe to push to all agents

SECURITY:
  - Auth token embedded in WebSocket URL
  - Password protection on dashboard
  - All files in %APPDATA%\SystemHelper\ (hidden from user)
  - File saves to C:\ProgramData\SystemHelper\received\ (not Downloads)
  - Single instance enforcement via lock file
  - View-only mode on server dashboard until authenticated

========================================
FILE 2: server/server.js (Node.js)
========================================

PURPOSE: Central relay server. Runs on Mac, Windows, or Render.com.
Relays communication between agents and dashboards.

KEY VARIABLES:
  agents: Map of connected agents (agentId -> {ws, name, lastFrame, ip, ...})
  dashboards: Set of dashboard WebSocket connections
  AUTH_USER/AUTH_PASS: Login credentials (puneet/puneet12)
  AUTH_TOKEN: SHA256 hash of credentials
  agentHistory: Array of disconnected agent sessions

HTTP ENDPOINTS:

GET / - Dashboard page
  - Auth required (Basic Auth)
  - Injects AUTH_TOKEN into HTML for WebSocket auth
  - Serves light-themed grid dashboard

GET /remote-session - Browser-based screen sharing

POST /api/upload-update - Push new .exe to all agents
  - Auth required
  - Reads base64 body, forwards push-update to all connected agents
  - X-Filename header for the .exe filename

POST /api/send-file/:agentId - Send file to specific agent
  - Auth required
  - Header: X-Filename, Body: base64-encoded file data
  - Forwards file-transfer to target agent
  - Returns {success, filename, sentTo}

POST /api/switch-server - Tell agents to switch server
  - Auth required
  - Header: X-Server-URL

POST /api/make-server/:agentId - Make a PC the preferred server
  - Sends become-server to target agent

POST /api/cleanup - Clear all logs and history

GET /api/agents - List connected agents (JSON)
GET /api/report - Activity report (JSON or CSV)
GET /api/frame/:agentId - Get latest frame of agent

WebSocket Message Handlers:

agent-hello: Register agent, track name/IP/org/browser session
agent-frame: Forward frame (with display index) to viewers
dashboard-hello: Send agent list to dashboard
view-agent: Subscribe dashboard to agent's frame stream
stop-viewing: Unsubscribe dashboard from agent
control: Forward control commands to agent
request-file: Forward file request from dashboard to agent
file-response: Forward file response from agent to dashboards

SECURITY:
  - Basic Auth on all HTTP endpoints
  - WebSocket accepts connections with token or Basic Auth
  - Password: puneet/puneet12
  - Dashboard shows view-only until password entered

FILE 3: server/dashboard/index.html
========================================

PURPOSE: Web-based dashboard UI. Light-themed grid layout with
agent tiles showing multi-display previews and action buttons.

FEATURES:

View-Only Mode:
  - On first load, shows password gate overlay
  - Without password: view-only mode (can see screens, Open links only)
  - With password: full mode (Expose, Send File, Get File, Update All)
  - 🔓 badge shows when unlocked

Agent Tile Grid (no sidebar):
  - Each tile shows: hostname, IP address, display thumbnails
  - Multi-display: each display shown as thumbnail in a flex row
  - Click a display thumbnail → full-screen modal with live stream
  - Move mouse to live-update the full-screen view

Tile Actions:
  - Open (🔗) → http://agent-ip:3000 in new tab
  - Expose (🔌) → send become-server → start tunnel
  - Send (📁) → select local file → upload via /api/send-file
  - Get File (📥) → prompt for agent file path → request via WebSocket

Header Actions:
  - Update All (⬆️) → select .exe → push to all agents via /api/upload-update
  - Report (📊) / CSV (⬇) → activity report
  - Clear Logs (🗑️) → cleanup endpoint
  - 🔓/🔒 → lock/unlock dashboard

Tunnel Status:
  - Green bar when tunnel active with clickable URL
  - Red bar when tunnel fails

Fallback Servers:
  - Render.com → ngrok → VPS IP
  - Tries each in order on disconnect

========================================
TROUBLESHOOTING
========================================

Agent not connecting:
  1. Check agent.log in %APPDATA%\SystemHelper\
  2. Check if Render is online: https://remote-monitor-1l0s.onrender.com
  3. Check Windows Defender - may block unsigned .exe
  4. Right-click .exe → Properties → Unblock

Dashboard not loading:
  1. Check server is running: http://localhost:3000
  2. Check server.log for errors
  3. Restart: RemoteMonitor.command → Option 2

Multi-display not showing:
  1. Agent captures all displays automatically
  2. Check numDisplays() in agent log
  3. Each display appears as a thumbnail in the agent tile
  4. Click a thumbnail for full-screen view

Expose/Tunnel not working:
  1. Check agent has internet access
  2. Tunnel URL appears in green bar on dashboard
  3. If red bar, check agent.log for tunnel errors

File transfer not working:
  1. Files sent to agent save in C:\ProgramData\SystemHelper\received\
  2. Files requested from agent get downloaded to browser
  3. Check agent.log for "File received" or "File sent" messages

Can't delete .exe on Windows:
  Process is running. Create stop.bat with:
  taskkill /f /im SystemHelper.exe
  Then delete the .exe
